# API contract: harvey-app IPC (issue #19)

The source of truth is the generated `ui/src/bindings.ts`. This file fixes its shape so the back and front tasks
agree before it exists.

## Result envelope (tauri-specta)

Every command returns `Promise<Result<T, AppError>>`:

```ts
type Result<T, E> = { status: "ok"; data: T } | { status: "error"; error: E };
```

## `AppError`

Internally tagged on `kind`, snake_case:

```ts
type AppError =
  | { kind: "not_found" }
  | { kind: "validation"; field: string; key: string }
  | { kind: "conflict"; key: string }
  | { kind: "permission_denied"; resource: string }
  | { kind: "calendar_unavailable" }
  | { kind: "maintenance" }
  | { kind: "schema_mismatch" }
  | { kind: "storage" }
  | { kind: "internal" };
```

- `field`, `key` and `resource` are identifiers (`"siren"`, `"validation.siren.invalid"`, `"calendar"`), never user
  values, personal-data ids, paths or SQL.
- Message key = `error.<kind>`, the same in Rust (`AppError::message_key()`) and TS (`errors.ts`).

Wire examples:

```json
{ "kind": "not_found" }
{ "kind": "validation", "field": "siren", "key": "validation.siren.invalid" }
{ "kind": "permission_denied", "resource": "calendar" }
```

## Commands

| Command | Args | Ok | Errors | Capability |
|---|---|---|---|---|
| `app_info` | none | `AppInfo` | `internal` (not expected) | `main` |

```ts
type BuildChannel = "dev" | "release";
type AppInfo = { version: string; build_channel: BuildChannel };
```

- `version`: the app version (`0.1.0` today).
- `build_channel`: `"dev"` when the bundle identifier ends in `.dev` (`com.harvey.dev`), otherwise `"release"`.

Generated call: `commands.appInfo()` (tauri-specta camel-cases names in TS). `forWindow` takes the TS name of the
base command.

## Events

None yet (`collect_events![]`). `entity_changed` and the other events come with #36 and later issues.

## WS3 wrappers

`<window>__<base>` has the same args and result as `<base>`. TS name: camelCase of the whole name, e.g.
`settings__app_info` → `settingsAppInfo`, `tray_popover__app_info` → `trayPopoverAppInfo`. None ships in production yet.

## Capability permission names

The app command `foo_bar` is granted by the permission `allow-foo-bar` (generated by `tauri-build` from
`AppManifest::commands`). A wrapper such as `settings__app_info` is granted by `allow-settings--app-info`.
